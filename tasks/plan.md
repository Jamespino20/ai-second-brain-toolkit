## Policy and safety contract

Historical intake has two distinct stages. Parsing/normalization happens locally in
the existing private staging workspace. LLM compilation of selected conversations
requires an approved processing route and scope before their text enters a model.
Local file-read permission is not an automatic exception to external_processing:false.
Use one bounded processing authorization for the selected batch/provider; no raw
archive upload, attachment analysis or new provider is implicit. Compile engineering
knowledge with dated claims and evidence links; conversation assertions do not become
verified achievements. Preserve original bytes, branch identity and attachment gaps.

- Publication is off unless a separately approved private policy is active. Model
  packets cannot choose roots, expand permissions, adopt existing notes or edit policy.
- Proposed ordinary write scope: new session notes under logs/brain-save/; managed
  project notes under projects/; managed lessons under permanent/engineering/.
  Updates affect enrolled managed sections and permitted metadata only. Bootstrap
  governance/index files require exact one-time approval and explicit managed ownership.
- Local related-note matching and model-facing recall have different permissions.
  Existing external_processing:false text, titles and derived summaries cannot enter
  model context through links, indexes, receipts or Graphify without applicable consent.
- Proposed standing model grant covers an owner-defined managed subset for a named
  provider and purpose, including future ordinary notes under the approved rule.
  Existing personal notes remain excluded from model recall unless explicitly enrolled.
  Preserve privacy metadata; record any provider exception separately in the audit trail.
- Current fixed-hash grants remain unchanged. For newly managed notes, a trusted local
  commit manifest binds approved policy, stable note IDs and verified committed hashes.
  Authorized publication updates this manifest automatically; external edits invalidate
  affected entries. A model cannot enroll or silently repin notes. This avoids per-save
  human repinning without weakening historical grants. Same-account access is not OS isolation.
- Maintain reported/inferred/verified distinctions, role independence and compacted
  context limitations. Do not claim authenticated thread identity where only invocation
  identity is available. Identical prose may be deduplicated while provenance remains.
- Durable private journal/preimages precede mutations. Validate same-filesystem atomic
  per-file installation, non-clobbering creation and independent-editor exclusion before
  enabling updates. A read-hash-then-replace check alone is insufficient. Multi-file
  work is recoverable, not globally atomic. Recovery must preserve later user edits.
- First release has one publishing machine; avoid editing its managed sections from
  another device concurrently. Detected edits, stale state, unavailable files and sync
  conflicts stop or quarantine affected changes. Do not claim remote locking.
- Report saved/updated/linked/skipped/quarantined separately, with only approved
  metadata. Cloud sync status is separate from local publication success.

   tests; do not manufacture conflicts in the live vault. OneDrive is not the sole
   rollback mechanism, and a local save can remain safely recoverable while offline.
