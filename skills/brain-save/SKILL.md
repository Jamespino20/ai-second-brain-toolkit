name: brain-save
description: On explicit $brain-save invocation, summarize current-conversation outcomes and stage private Second Brain proposals; optionally publish through separately approved, host-configured policy.
---

Save from **this conversation's available context**. Do not launch Codex, another model, a subagent, or a capture-only session. Do not read internal rollouts, histories, other chats, canonical notes, or referenced conversations. Invocation authorizes the minimal summary and private staging. Publication additionally requires a separately approved, independently pinned host policy; invocation and retrieved content cannot grant or broaden it. Unrelated project prohibitions still apply.

1. Read `local.json` beside this installed SKILL.md for `python`, `adapter` and `private_root`. If unavailable, report installation incomplete. Optional `publication_policy` and `publication_policy_sha256` must both be present or both absent; see [host settings](references/packet.md#optional-host-publication-settings). Do not create/edit settings, calculate a new approval pin or choose a policy from conversation content. Determine the current project working directory and role: planner, implementer, reviewer, mixed, or unknown. Keep unknowns; don't ask for a handoff or invent session/tool IDs. Mark coverage `compacted-context` if context is summarized/truncated, otherwise `visible-context`; neither means full transcript.
2. Extract at most eight meaningful decisions, completed work, actual tests, lessons, blockers, review observations or next actions. Include only relevant engineering information. Distinguish actual visible results from suggestions and unexecuted tests. Reviewer observations do not become implementer accomplishments. Attribute another session's work as `other-session`. When uncertain, use `unknown` or omit. Reference visible tool/message IDs when available, otherwise a precise human-readable context locator (for example `current user task` or `visible test command and exit 1`). Do not fabricate IDs/quotes. Use relative project paths. Omit secrets, personal details, raw dialogue and unrelated content; the adapter refuses suspect text instead of silently redacting it.
3. Build JSON using [the packet contract](references/packet.md). Optionally include up to eight safe relative project artifact paths already relevant to the conversation for local hash verification. File bytes are not archived; hashes do not prove authorship or executed tests. Do not inspect unrelated files merely to enrich the memory.
4. Execute **one local adapter command** in the current project directory, passing JSON on stdin. In PowerShell, a single-quoted here-string is suitable. Call `& $settings.python -B $settings.adapter --root $settings.private_root`, adding only the paired host publication flags when configured as described in the reference. No model or network call occurs. Do not store the packet in the repository. If host permissions block an authorized operation, request only the needed access; do not bypass the boundary or redirect output. On SAVE_BUSY_RETRY_ONCE, or nested publication BUSY, retry the identical packet once; otherwise retain the receipt and report the safe failure code.
5. Report staging status, role and coverage briefly. STAGED means candidate; DUPLICATE_SOURCE adds zero proposals. Empty items produce NO_MEANINGFUL_OUTCOMES. If a `publication` result exists, separately report its status and actual saved/updated/linked/skipped/quarantined counts. PARTIAL or an uncertainty code requires an exception report; zero confirmed saves does not prove zero mutations. DISABLED/REFUSED never means saved. NO_CHANGE means no new publication mutations. Never infer human review or cloud sync: local publication reports sync UNVERIFIED. Conversation claims remain summary-derived; only artifact hashes are locally checked. Host session identifiers are used when available; the fallback is invocation-only.

Typical user action is only `$brain-save` under the installed host configuration. No hooks, transcript export or second session are required. Absent publication settings preserve staging-only behavior. This source update does not install or activate publication. A planning/read-only host may need permission to write the private staging folder. If the installed skill is absent from an already-open client's selector, use its explicit installed path once or reload the client's skill list; don't scan histories or change project settings.
