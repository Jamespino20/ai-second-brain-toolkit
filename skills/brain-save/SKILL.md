---
name: brain-save
description: On explicit $brain-save invocation, summarize essential outcomes from this current Codex conversation and stage a private review-only Second Brain proposal using the existing local toolkit.
---

Save from **this conversation's available context**. Do not launch Codex, another model, a subagent, or a capture-only session. Do not read internal rollouts, histories, other chats, canonical notes, or referenced conversations. Never publish. Invocation authorizes only this minimal current-context summary and local staging; unrelated project prohibitions still apply.

1. Read `local.json` beside this installed SKILL.md for `python`, `adapter` and `private_root`. If unavailable, report installation incomplete. Determine the current project working directory and role from this conversation: planner, implementer, reviewer, mixed, or unknown. Keep unknowns; don't ask for a handoff or invent session/tool IDs. Mark coverage `compacted-context` if context is summarized/truncated, otherwise `visible-context`; neither means full transcript.
2. Extract at most eight meaningful decisions, completed work, actual tests, lessons, blockers, review observations or next actions. Include only relevant engineering information. Distinguish actual visible results from suggestions and unexecuted tests. Reviewer observations do not become implementer accomplishments. Attribute another session's work as `other-session`. When uncertain, use `unknown` or omit. Reference visible tool/message IDs when available, otherwise a precise human-readable context locator (for example `current user task` or `visible test command and exit 1`). Do not fabricate IDs/quotes. Use relative project paths. Omit secrets, personal details, raw dialogue and unrelated content; the adapter refuses suspect text instead of silently redacting it.
3. Build JSON using [the packet contract](references/packet.md). Optionally include up to eight safe relative project artifact paths already relevant to the conversation for local hash verification. File bytes are not archived; hashes do not prove authorship or executed tests. Do not inspect unrelated files merely to enrich the memory.
4. Execute **one local adapter command** in the current project directory, passing the JSON on stdin. In PowerShell, a single-quoted here-string is suitable. Read settings and call `& $settings.python -B $settings.adapter --root $settings.private_root`; pipe the JSON here-string into that call. No model or network call occurs. Do not store the packet in the repository. If the host blocks staging writes, request only the required private-root permission; do not bypass the sandbox or move output to the live vault. On SAVE_BUSY_RETRY_ONCE, retry the identical packet once; otherwise stop with the safe failure code.
5. Report status, proposal path, role and coverage briefly. STAGED means candidate, not accepted/published. DUPLICATE_SOURCE adds zero proposals. If nothing meaningful exists, send an empty items list and report NO_MEANINGFUL_OUTCOMES. Never claim conversation summaries are independently verified facts: only artifact hashes are locally checked. The adapter uses host session identifiers when available and labels the fallback as invocation-only, not an actual thread ID.

Typical user action is only `$brain-save`. No hooks, settings changes, enable switch, manual handoff, transcript export or second session is required. A planning/read-only host may need permission to write the private staging folder. If the installed skill is absent from an already-open client's selector, use its explicit installed path once or reload the client's skill list; don't scan histories or change project settings.
