# Stage 1: inspect connection settings using metadata only

Date: 2026-11-05. Status: one exact owner-approved metadata-only session completed; see execution checkpoint below.
This precedes fictional-note recall. Neither stage grants canonical access.

## What this experiment can establish

The owner-supplied interface shows OAuth and disabled advanced settings before a
server URL is entered. Official [connection instructions](https://developers.openai.com/plugins/deploy/connect-chatgpt)
start with an endpoint; [authentication instructions](https://developers.openai.com/plugins/build/auth)
require the exact callback from management. Neither establishes that the target
UI reveals its callback before Create or authorization. This experiment tests that
specific question, and must report failure if the UI needs those actions first.

## Concrete permission to prepare, then request

Package only the reviewed discovery-only module, its reviewed bounded launcher,
the pinned standalone helper, exact empty configuration and pending metadata-only
manifest. Include the source/runtime/contract reviews and dependency checks.
Independent package comparison precedes an owner-facing execution request.
That request names the owner-operated ChatGPT surface, a maximum 15-minute session,
the precise artifact pins, derived hostname rule, recipient scope and cleanup.
No service starts while any package or owner state is pending.

The proposed flow retains an exclusive loopback socket, starts one owned temporary
Quick Tunnel, obtains and validates its generated hostname, then serves only the
reviewed public discovery documents. All OAuth and MCP requests refuse. Source has
no reader, note, grant, token, client-ID/callback learning or recall promotion switch.
Only the generated origin can be bound; a different origin stops the session.
Native preliminary socket evidence is narrower than actual launcher/cleanup proof.

The owner would enter the supplied /mcp URL and inspect advanced OAuth settings.
They would copy only the displayed client setup choices and exact public callback,
if available. No Create, Install, Connect, consent, password or secret entry is
included in Stage 1. Browser automation remains stopped; the owner operates this
inspection. If the UI requires a forbidden step, close the form and stop.

## Data, recipients and cost

No fictional or personal notes are loaded in Stage 1. The public URL exposes only
intended OAuth discovery metadata and denial responses, so possession of the URL
must not be described as an authentication barrier. Cloudflare provisions and
relays the tunnel; OpenAI fetches the endpoint metadata when the owner enters it.
Ordinary network/device metadata and the temporary origin/port are involved.

Upstream helper source also initializes Sentry and can report errors/panics.
The proposal must explicitly name Sentry and potential diagnostic/device metadata
(for example machine/OS/version and error/stack/path information), or establish
a verified disable mechanism first. No disable mechanism is currently proved;
do not hide this recipient behind a claim of Cloudflare/OpenAI-only traffic.
Actual telemetry payload and source-to-binary behavior have not been reproduced.
Never collect/persist raw OAuth query/state/code/token/cookie or account credentials.

[Cloudflare documents temporary Quick Tunnels as free/account-free](https://developers.cloudflare.com/workers/wrangler/commands/tunnel/#tunnel-quick-start).
They provide changing hostnames, no SSE and no uptime guarantee. This is a test,
not a permanent free hosting claim. No billing account, API key/model call, paid
domain, trial, credit purchase or plan upgrade is proposed. Preserve the owner's
$0 additional-spend boundary and existing included ChatGPT usage limits.

## End and next gate

Stop/reap only the owned helper and stop the local metadata server before releasing
the retained root socket. Record intent/final receipt and exit status, preserve
all existing Work/CLI connections and confirm the temporary endpoint ceases serving.
No broad process kill or old configuration rollback. Cleanup failure requires
supervised hold-open/manual intervention; source proof does not establish recovery
after a crash, power loss or forcible termination.

Even a successful Stage 1 only supplies candidate connection settings. A separate
exact active fictional-note profile, runtime/recipient review and owner connection
consent precede actual search/read in a fresh ordinary Chat. Use search-first and
an initial five-line read; preserve grant/bounds and stop on refusal. Real account
association and read-only external behavior must be established at that stage.
Regular Chat saving and existing-note updates remain separate work.
